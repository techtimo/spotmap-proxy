# Spotmap Proxy

A lightweight Docker service that bridges two GPS tracking integrations to [Spotmap](https://github.com/techtimo/spotmap) WordPress installations:

- **Zoleo** — receives webhook pushes from Zoleo satellite communicators and forwards them to the correct WordPress site
- **OGN/FLARM** — maintains a persistent TCP connection to the OGN APRS network and forwards glider positions by device ID

One proxy instance can serve multiple WordPress installations. Routing tables are stored in SQLite and survive restarts.

---

## Prerequisites

- Docker and Docker Compose v2

---

## Quick Start

```bash
# 1. Clone the repo
git clone https://github.com/techtimo/spotmap-proxy.git
cd spotmap-proxy

# 2. Set required environment variables (see Environment Variables section below)
# Edit .env: set ADMIN_KEY and PROVISION_KEY to long random strings

# 3. Start the container
docker compose up -d

# 4. Verify it's running
curl http://localhost:8080/health
# → {"ok":true}
```

## Security Model

Two keys protect different layers:

| Key | Where it lives | What it protects |
| --- | --- | --- |
| `PROVISION_KEY` | Baked into the Spotmap WordPress plugin | Access to the `/provision/*` API |
| `ingest_key` | Generated by WordPress, never shown to the end user | Proves ownership of a specific route; required to update or delete it |
| `ADMIN_KEY` | Server operator only | Full admin access — list and force-delete any route |

A site that knows `PROVISION_KEY` can register a new device. It cannot modify or delete a route it doesn't own because it won't have the matching `ingest_key`. The proxy enforces this on every self-service delete.

## Adding a Zoleo Route

A route maps a Zoleo account ID to a WordPress ingest endpoint.

```bash
curl -X POST http://localhost:8080/provision/routes/zoleo \
  -H "Authorization: Bearer $PROVISION_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "zoleo_account_id": "YOUR_ZOLEO_ACCOUNT_ID",
    "wordpress_url": "https://example.com/wp-json/spotmap/v1/ingest/zoleo",
    "ingest_key": "your-spotmap-feed-key",
    "label": "My Zoleo Device"
  }'
```

`label` is optional. If the route already exists and the `ingest_key` matches, the `wordpress_url` and `label` are updated in place.

Then configure the webhook URL in the **Zoleo developer portal** to:

```
https://<your-proxy-domain>/zoleo
```

## Adding an OGN Route

A route maps a device ID to a WordPress ingest endpoint. Adding or removing a route automatically reconnects to the OGN APRS network with an updated filter.

```bash
curl -X POST http://localhost:8080/provision/routes/ogn \
  -H "Authorization: Bearer $PROVISION_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "address_type": "FLR",
    "device_id": "4B51BF",
    "wordpress_url": "https://example.com/wp-json/spotmap/v1/ingest/ogn",
    "ingest_key": "your-spotmap-feed-key",
    "label": "My Glider"
  }'
```

`label` is optional. If the route already exists and the `ingest_key` matches, the `wordpress_url` and `label` are updated in place.

Valid `address_type` values:

| Value | Protocol |
|---|---|
| `FLR` | FLARM |
| `ICA` | ICAO |
| `OGN` | OGN tracker |
| `FNT` | FANET |
| `PAW` | PilotAware |

### Error responses

| HTTP | Reason |
|---|---|
| `400` | Missing or invalid field |
| `409` | Device already registered to a different site, or the proxy has reached its route limit |
| `429` | Rate limit: max 2 successful provisions per minute per IP |

The `409` message is intentionally the same for both the conflict and the capacity case — the plugin does not need to distinguish between them.

## Removing a Route

**Self-service** — requires the matching `ingest_key` to prove ownership:

```bash
# Remove a Zoleo route
curl -X DELETE http://localhost:8080/provision/routes/zoleo/YOUR_ZOLEO_ACCOUNT_ID \
  -H "Authorization: Bearer $PROVISION_KEY" \
  -H "Content-Type: application/json" \
  -d '{"ingest_key": "your-spotmap-feed-key"}'

# Remove an OGN route
curl -X DELETE http://localhost:8080/provision/routes/ogn/FLR/4B51BF \
  -H "Authorization: Bearer $PROVISION_KEY" \
  -H "Content-Type: application/json" \
  -d '{"ingest_key": "your-spotmap-feed-key"}'
```

**Admin** — no `ingest_key` needed:

```bash
curl -X DELETE http://localhost:8080/admin/routes/zoleo/YOUR_ZOLEO_ACCOUNT_ID \
  -H "Authorization: Bearer $ADMIN_KEY"

curl -X DELETE http://localhost:8080/admin/routes/ogn/FLR/4B51BF \
  -H "Authorization: Bearer $ADMIN_KEY"
```

## Listing All Routes

```bash
curl http://localhost:8080/admin/routes \
  -H "Authorization: Bearer $ADMIN_KEY"
```

`ingest_key` values are redacted to the first 4 characters in the response.

## Metrics

Prometheus metrics are exposed on port `9877` at `/metrics`. Useful queries for Grafana:

| Metric | Description |
|---|---|
| `spotmap_zoleo_routes_total` | Number of Zoleo routes currently registered |
| `spotmap_ogn_routes_total` | Number of OGN routes currently registered |
| `ogn_aircraft_lat{identifier}` | Latest latitude by device ID |
| `ogn_aircraft_lon{identifier}` | Latest longitude by device ID |
| `ogn_aircraft_alt_meters{identifier}` | Latest altitude in metres |
| `ogn_aircraft_last_seen_timestamp{identifier}` | Unix timestamp of last position |

Aircraft metrics for devices not seen within `OGN_STALE_SECONDS` (default 300 s) are automatically removed.

To alert on route-table flooding:

```promql
spotmap_zoleo_routes_total + spotmap_ogn_routes_total > 80
```

## Viewing Raw Zoleo Payloads

Because the Zoleo payload schema is not publicly documented, the proxy logs every raw incoming body to `/data/zoleo-payloads.log`. After the first real Zoleo push, inspect the log to confirm field names.

```bash
docker compose exec proxy cat /data/zoleo-payloads.log
```

## Environment Variables

| Variable | Required | Default | Description |
|---|---|---|---|
| `ADMIN_KEY` | yes | — | Bearer token for all `/admin/*` endpoints |
| `PROVISION_KEY` | yes | — | Bearer token for all `/provision/*` endpoints |
| `PORT` | no | `8080` | HTTP listen port |
| `DATABASE_PATH` | no | `/data/spotmap-proxy.sqlite` | SQLite file path |
| `MAX_ROUTES` | no | `100` | Maximum total routes (Zoleo + OGN combined) |
| `METRICS_PORT` | no | `9877` | Prometheus metrics listen port |
| `OGN_STALE_SECONDS` | no | `300` | Seconds before an aircraft's metrics are removed |
| `ZOLEO_BASIC_AUTH_USER` | no | — | If set, enforce HTTP Basic Auth on `POST /zoleo` |
| `ZOLEO_BASIC_AUTH_PASS` | no | — | Password for Zoleo Basic Auth |
| `ZOLEO_LOG_PATH` | no | `/data/zoleo-payloads.log` | Path for raw Zoleo payload log |
| `AIS_API_KEY` | no | — | AISstream.io API key; AIS tracking disabled if absent |

## API Reference

### Public

| Method | Path | Auth | Description |
|---|---|---|---|
| `GET` | `/health` | none | Returns `{"ok":true}` |
| `POST` | `/zoleo` | Basic (optional) | Zoleo webhook receiver |

### Provision (`Authorization: Bearer <PROVISION_KEY>`)

| Method | Path | Description |
| --- | --- | --- |
| `POST` | `/provision/routes/zoleo` | Add or update a Zoleo route |
| `DELETE` | `/provision/routes/zoleo/:id` | Remove own Zoleo route (requires `ingest_key` in body) |
| `POST` | `/provision/routes/ogn` | Add or update an OGN route |
| `DELETE` | `/provision/routes/ogn/:address_type/:device_id` | Remove own OGN route (requires `ingest_key` in body) |

### Admin (`Authorization: Bearer <ADMIN_KEY>`)

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/admin/routes` | List all routes (keys redacted) |
| `DELETE` | `/admin/routes/zoleo/:id` | Force-remove any Zoleo route |
| `DELETE` | `/admin/routes/ogn/:address_type/:device_id` | Force-remove any OGN route |

## Notes

- **GPS points are never stored** — packets are forwarded immediately and dropped. If WordPress is unreachable the point is lost (by design).
- **OGN reconnect** — Adding or removing an OGN route triggers a single reconnect to APRS with the updated filter. No container restart needed.
- **Same device, two sites** — not currently supported. A device can only route to one WordPress site at a time. Registering to a second site returns `409`.
- **Zoleo schema** — the Zoleo payload format is not publicly documented. Use the raw payload log to verify field names before finalising the `handle_zoleo()` function in the Spotmap plugin.
